# Joblume Phase 7: reach the employer

## 1. Problem (observed)
39 pending matches, most with no contact email or WhatsApp number to apply through. Causes: (a) `server/src/services/email` only uses Hunter and role-mailbox guesses; nothing reads contact details the employer printed in the posting; (b) JSearch (LinkedIn/Indeed) and Remotive have no recorded scan on the Last scan card; (c) cards do not say HOW to apply; (d) the user wants more sources.

## 2. Scope
1. **Contact extraction from the posting.** A pure function `extractContacts(text)` returns emails (employer-published, deduplicated, lower-cased, max 5) and WhatsApp numbers (from `wa.me/<digits>`, `api.whatsapp.com/send?phone=`, or phone numbers within about 40 characters of the word "whatsapp"; normalised to digits with country code when written as +234… or 0XXXXXXXXXX Nigerian format → 234…). Ignores obviously non-contact addresses (noreply, no-reply, example.com, image filenames like x@2x.png, privacy/support/abuse mailboxes unless nothing else), strips trailing punctuation, handles "name [at] company dot com" and "name(at)company.com" obfuscations. Pure, no I/O.
2. **Use it.** New email candidate source `posting` (highest rank, confidence 95, shown as "Published in the job post"). `applications.email_source` accepts `posting`. The find-email step first extracts from the job description and, when found, saves those as the first candidates (before Hunter and guesses; Hunter still runs only if no posting email was found, to save quota). A posting address is NOT guessed so it needs no confirmation tick, but it is NOT Auto-eligible (Auto stays Hunter-confirmed only; do not change the Auto rules). WhatsApp numbers are stored on the application (`whatsapp_number`, digits only) and shown as a "Message on WhatsApp" button that opens `https://wa.me/<number>?text=<short intro, URL-encoded>`; it only opens the chat, never sends anything. The intro text is the first 300 characters of the cover letter.
3. **Backfill.** A one-off server script `npm run backfill:contacts -w server` that runs the extraction over existing pending applications' jobs and fills candidates / whatsapp_number where empty (never overwrites a manual or hunter address; dry-run flag `--dry`).
4. **Apply-method badge.** Each queue card and the job detail show one of: "Email" (has any email candidate), "WhatsApp" (has a number and no email), "Employer site" (neither). Queue gets a filter chip "Has email". Web and mobile.
5. **Catch-up scans.** At worker start, any source that is scheduled but has no `scan_runs` row newer than its interval (JSearch with a key, Remotive, and every other source) is enqueued once immediately. JSearch's catch-up respects its monthly quota.
6. **Working Nomads.** `https://www.workingnomads.com/api/exposed_jobs/` (public JSON; verified to return an array with `url`, `title`, `description` HTML, company, location, tags, publish date). Scraper behind the `Scraper` interface with a fixture of the real response trimmed, attribution = the board's own job URL and the name shown; cursor pagination is not needed for one page. Add to sources, 2-hour schedule, cap 60, remote board in the prefilter (REMOTE_BOARDS).
7. **Talent platforms checklist.** `docs/talent-platforms.md`: Remotebase, Index.dev, Somewhere, Upstack, Working Nomads, Remote.co, Turing, Toptal, Andela (links to their sign-up/apply pages as known), with one line on what each is, plus a note that they are join-once marketplaces, not scannable listings. Link it from the README. No code.

## 3. Out of scope
LinkedIn/Indeed page scraping (blocked; JSearch only), scraping or guessing personal phone numbers beyond what the posting itself publishes, sending WhatsApp messages automatically, Remote.co (unreachable at build time), Auto mode changes, Hunter changes.

## 4. Safety
Nothing sends without the user's click; WhatsApp opens a chat only. Extracted addresses are untrusted text: validated with a strict email check before storage, length-capped, shown as plain text. A posting email appears in the same Recipient box with the same Send confirmation flow. No change to Auto rules, locks or caps.

## 5. Testing
Table-driven tests for `extractContacts` (Nigerian numbers 0803…, +234, wa.me links, obfuscated emails, noreply/example filtered, lookalike false positives like version strings, file names, 'a@b' without TLD); finder tests (posting first, Hunter skipped when posting email found, manual/hunter never overwritten); backfill dry-run test; catch-up scheduler test; Working Nomads fixture test; web and mobile badge/filter/WhatsApp-link tests (URL encoding, only digits allowed).
